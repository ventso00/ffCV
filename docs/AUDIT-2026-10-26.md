# Revue FF-ScoutMetrics — 26 octobre 2026

## Résultat et périmètre

Revue du parcours utilisateur, du Worker, des adaptateurs, de la normalisation, du rendu, des exports, du cache et du stockage prévu. Tests locaux et requêtes réelles sur les deux UID fournis. Ceci n’est pas un audit de pénétration ni une recette réseau effectuée physiquement à Madagascar.

Le formulaire ne demande que l’UID. Les profils et les contrôles du personnage sont verrouillés. La mention demandée est présente : « Profil en lecture seule. Pseudo, niveau et statistiques proviennent de la source ; tu ne peux pas les modifier ici. »

Les UID 8678687120 et 23146856 sont admis par défaut sur déclaration du porteur du projet, sans prétendre vérifier leur pays ou leur propriétaire. MG_PILOT_ROSTER remplace entièrement cette liste, même avec `{}`. Les autres UID restent refusés. Un UID ne permet pas à lui seul d’établir une résidence malgache.

Pour une région inconnue, le backend essaie les routes Community SG, IND puis BR, uniquement après un 404. Il s’arrête sur refus d’authentification, quota, erreur réseau ou réponse incohérente. Une région administrative connue évite cette résolution. Aucun choix de serveur n’est demandé au visiteur. Cette résolution est testée avec des fixtures ; elle reste à valider avec une clé active et des comptes réels.

## Tests réels des sources

Chaque service ci-dessous a été interrogé pour chacun des deux UID. Aucun n’a renvoyé de profil exploitable. Le journal séparé conserve les URL, réponses et la date. Les requêtes SG servent de sondes techniques et ne prouvent pas que les comptes sont sur SG.

| Service | Résultat pour les deux UID | Décision |
|---|---|---|
| Free Fire Community `/info` | HTTP 401, AUTH_001, clé absente | Adaptateur conservé, accès requis |
| NF Token `/player-info`, auto région | Échec réseau | Non intégré |
| BT System `/api/info_player`, clothes=true | HTTP 408, page hébergeur | Non intégré |
| PRINCE-LKTEAM sur Render | HTTP 404, Not Found | Non intégré |

Ces erreurs ne démontrent ni l’invalidité des UID ni une panne permanente des services. Aucun pseudo, niveau, rang, personnage ou skin n’a pu être confirmé. Aucun CV réel n’a donc été créé pour ces comptes.

## Plateformes et limites documentées

- [Free Fire Community](https://developers.freefirecommunity.com/en/docs) : fournisseur communautaire, clé nécessaire, endpoints distincts pour profil, statistiques et images. L’application ne consomme actuellement que le profil ; K/D, headshots et rendus restent indisponibles.
- [MooGold](https://doc.moogold.com/) : adaptateur signé `product/validate` prêt, testé avec réponses simulées. Nécessite accès partenaire et produit Free Fire approprié. Valider un pseudo ne fournit pas les statistiques ou la tenue. Aucun appel de commande ou paiement.
- [Codashop](https://br.support.codashop.com/hc/en-us/articles/360003977856-How-to-purchase-diamonds-on-Free-Fire) : parcours de recharge à partir de l’UID. Aucune preuve collectée qu’il expose niveau, K/D, headshots, inventaire ou skin. Ne pas présenter une validation de paiement comme une API de profil complet.
- [UniPin](https://developer-docs.unipin.com/) : documentation partenaire identifiée, accès et couverture Madagascar non validés. Pas d’intégration déclarée opérationnelle.
- [NF Token](https://github.com/ravi252/Freefireapi), [BT System](https://hostfreefire-api.squareweb.app/docs-api/playground), [FWX](https://github.com/lucasribeiroxzz/FreeFire-Api-Docs), [PRINCE-LKTEAM](https://github.com/PRINCE-LKTEAM/Free-Fire-API) : documentations de leurs auteurs, sans garantie Garena ; disponibilité non démontrée par nos essais.
- [Client communautaire](https://github.com/0xMe/FreeFire-Api/blob/main/Api/InGame.py) : appels internes nécessitant authentification et protocole du jeu. `need_gallery_info` ne prouve pas un accès à tout l’inventaire. Non branché au site.
- [Catalogue Garena](https://ff.garena.com/en/chars) : utile pour identifier un personnage, insuffisant pour connaître la tenue réellement équipée d’un UID.

Le script alternatif Shop2Game est un prototype non validé. Aucun CAPTCHA contourné, aucune interception de session, aucun paiement lancé. Une source de recharge ne remplace pas le fournisseur de données détaillées.

## Architecture et constat par fonction

| Fonction | État |
|---|---|
| Frontend | HTML/CSS/JS, canvas ; textes injectés avec textContent, champs source désactivés |
| Backend | Cloudflare Worker ESM ; endpoint GET `/api/v1/player/:id`, pas de mutation de profil |
| Qualité des données | UID retourné contrôlé, champs absents conservés inconnus, source et date conservées |
| Skin actuel | Aucun rendu validé ; illustration uniquement dans la démo, jamais affectée aux comptes importés |
| Animation | Carte en perspective CSS, image 2D ; pas de modèle 3D du personnage |
| Export | PNG/PDF/JSON, démo non exportable ; un fichier externe n’est pas signé ni inviolable |
| Secrets | Fournisseurs appelés côté serveur, clés non embarquées dans le client |
| Protection API | Validation UID, timeout, limite de réponse, refus des redirections, CSP et rate limit |
| Quotas | Six recherches/minute/IP par isolate ; pas de quota distribué garanti |
| Stockage | Schéma SQLite/D1 fourni, non déployé ; pas encore d’historique persistant |
| Cache | Profils jusqu’à cinq minutes côté serveur ; API exclues du cache hors connexion |
| Recharge | Simulation seulement, prix inconnu, paiement et commande désactivés |
| Madagascar | Public cible et admission administrative ; pas de géolocalisation du compte |

## Reste indispensable avant ouverture publique

Configurer un accès fournisseur valide côté serveur, confirmer les profils des deux UID et leur région avec cet accès, puis valider un service de rendu de tenue avec correspondance exacte aux IDs équipés. Ensuite : base persistante, quotas partagés, liens de CV vérifiables, recette sur téléphones et réseaux malgaches. Le verrouillage de l’interface empêche l’édition normale ; il ne rend pas un PNG ou le navigateur du visiteur inviolable.
